# 选择与执行验证

[开发指南](README.md) · [验证工具](tooling/Inno.Tooling.Validation.md) · [测试项目](testing/README.md)

统一入口是 Build 的 `validate plan/run/full/evidence`。计划根据基线、工作区变化、实际 SDK 项目引用、imports 和附加输入选择 owner，显示编译前提、检查原因、环境及排除项。命令参数和状态语义以 [验证工具项目页](tooling/Inno.Tooling.Validation.md) 为准。

日常修改先读计划，再执行受影响的领域、契约或集成检查。无需窗口、GPU 和原生部署的领域套件与 Native 套件按执行前提隔离；真实原生生命周期仍由所属 backend 验证。

架构、领域单元、公共契约、集成、Native、产品/设备、性能/长期运行分别提供证据。缺少环境、空发现、取消或缺少结果不能算成功。证据只在源码、测试、工具和环境输入仍匹配时复用。

普通 Editor 产品旅程使用 30,000 帧预算并等待正常退出，给异步脚本加载及实际工作流留出执行机会。必须完成八项工作流，以及全部实际面板的 100 次开关、120 帧资源准备和十一轮 full-GC 观察；帧预算耗尽但缺少完整证据仍失败。扩展生命周期使用 1,000 次开关、180,000 帧和 5,400 秒上限。报告记录实际循环数、耗时和正常退出状态，产品旅程耗时与日常契约反馈分别报告，普通功能旅程不代替长期运行。

纯文档导航与 agent 记录的结构检查不需要编译引擎；API 分片与可执行示例由对应项目的引用闭包验证。完整产品与设备矩阵显式执行，有限范围通过不代替完整认证。

## 耗时与异常调查

开发反馈没有统一的“30 秒／2 分钟／5 分钟”通过门槛。原生第三方库的冷编译、完整产品构建与小范围领域测试具有不同成本；单纯耗时较长不构成缺陷，也不为达到秒数而删减必要断言。

调查重点是实际依赖之外的重复构建、相同请求反复准备、缓存无故失效、锁竞争、取消不能收尾，以及子进程确实不再推进。结合当前阶段、构建日志、产物进度、锁持有者和子进程 CPU/I/O 判断；长时间没有控制台输出本身不能证明卡死。耗时退化报告用于提示同工作负载的变化，不自动把慢任务判为失败。

运行超时和取消仍用于限制失控执行，按具体任务及环境设置。达到运行上限应保留未完成状态、首次日志和诊断，再判断是正常工作量增加还是阻塞；不能当作通过或无限重跑。现有退休时限、功能性计时断言、资源预算和生命周期验证保持。周度冷构建、十轮热缓存与长期运行仍检查真实行为，正常功能任务不为满足统一耗时目标额外重复跑计时样本。
