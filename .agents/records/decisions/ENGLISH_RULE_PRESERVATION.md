# English rule preservation

The approved English modernization plan changes the language of active requirements without weakening them. Original rule identities, Git source locations and source hashes remain authoritative provenance. Historical source text remains available from those commits.

## Review method

Each translated unit has a line-by-line source-to-English correspondence in `coverage.json`. Nonblank lines include headings, nested requirements and examples. Each original numbered rule also identifies its translated clause. The selector validates complete correspondence, unchanged source identities, translated text identities and the existence of this review record before loading a unit.

These checks detect missing or unregistered edits. They cannot prove a translation preserves meaning. The implementing owner must compare the source and destination clauses, including every prohibition, exception, prerequisite and failure obligation, before registering the mapping. Changing hashes alone is not a semantic review. Subsequent substantive rule changes require an explicit approved change and a new review; this translation mechanism does not authorize them.

Keep the original source and English target in the same clause order so the mapping can be inspected without a second routing table. Blank-line formatting and relocated Markdown destinations are not requirement identities. Loading still returns complete units and all dependencies under the existing budgets.

## Current migration boundary

Only units with registered translations are English-reviewed here. Other units retain their original text and original full-text checks until their own translation review. This record is not a claim that all active rules, documentation or CI/CD migration is complete.
