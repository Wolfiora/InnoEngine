# Executable example evidence without repeated product acceptance

Engine reconciliation now binds each required example report to its exact selected pages, canonical catalog, mode, executable code blocks, SDK context and actual compilation reference identities. The source certificate retains those executable inputs and the platform report identities. Missing or changed examples cannot receive complete source certification.

The Docs producer independently authenticates the imported certificate, compares every current executable block and its host/runtime-script/editor-script context, and requires full coverage before freezing an artifact. Prose, headings and source positions can change without invalidating unchanged compiler inputs. Code, reference projects, projection mode or engine source changes invalidate that evidence. API-source verification remains a separate requirement; neither fresh indexing nor declaration presence establishes compiler or semantic acceptance.

Publication can carry a corrected document against the same certified engine input tree. It records the actual engine producer revision separately from the documented revision. It still requires a successful protected Docs producer, complete engine matrix, matching input tree, exact site archive digest and per-file identities. This does not inherit a green engine status across different source trees or permit a preview to publish.
