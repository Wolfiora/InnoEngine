# Real script compilation and CI receipt reconciliation

[Engine run 43191512147](https://github.com/Wolfiora/InnoEngine/actions/runs/43191512147) tests source `977655a3c63f528d26f2f677b375cf57fb3d1115`. Its macOS execution completed 334 checks successfully, with eight explicit NotApplicable results. Source/API comparisons, managed and Native examples, product journeys, Release builds, Support Pack preparation, AOT restore and the release bundle passed. The job then failed during receipt reconciliation. These facts do not make the failed aggregate a successful certification.

## Reproduced cause

The example compiler stored script references as a combined `AssemblyName:UPPERCASE_HASH` string, while the receipt verifier required each reference value to be a canonical lowercase SHA-256. Editor scripts combined two qualified identities with a semicolon. Previous tests checked that hashes appeared in the compiler output and separately tested a handcrafted receipt. Neither exercised the real producer/consumer boundary.

The producer now records `Inno.ScriptApi.Runtime` and, when selected, `Inno.ScriptApi.Editor` as distinct references with hashes of the exact frozen bytes used by Roslyn. The obsolete combined-identity method and field are removed. Receipt verification retains its strict hash checks and additionally requires the actual script surfaces: Runtime cannot borrow Editor, and Editor requires both. No host API, script export or runtime behavior changed.

The real compilation regression passes its generated report through the actual PowerShell receipt verifier for both script paths. Its dynamic script dependencies are declared as `InnoValidationInput` on the existing Architecture test owner, so changing that checker still selects its consumer regression. This does not create a second project or test selector.
