# Documentation input compatibility

Complete documentation publication previously required every source/API and executable-example obligation to appear in the current bounded run. That prevented an incremental run from completing a publication certificate even when unrelated owners had valid unchanged evidence. The implementation now keeps fresh execution and source-input compatibility distinct.

## Input and trust boundaries

Successful comparisons retain actual SDK-selected transitive owners, repository input contents, configuration, target, execution environment, restored package contents and the compared per-owner reference identity. Example proofs retain their actual projection-host closure as well as canonical executable blocks and mode. Source-only empty-surface inspection retains its source inputs without claiming compiled packages or foreign product execution.

The CI aggregate may import an exact-impact-baseline certificate only from a successful same-repository default-branch Engine CI run. It independently checks the workflow, event, repository IDs, commit, attempt, aggregate job, artifact metadata and downloaded archive digest. The archive contains exactly one bounded certificate. No cross-repository credentials are needed for this same-repository read; the separate Docs evidence relay still requires its organization App setup.

Compatibility uses the current plan whose bytes match the reconciled receipt. A selected or missing owner, changed recorded input, new evaluated input, changed checker input, environment/configuration mismatch, changed reference facts or changed example blocks prevents inheritance. Certificate-policy identity separately covers the producer's actual PowerShell reconciliation dependencies; unrelated release/cache/notification helpers do not enter that identity. Unknown relationships remain governed by the existing conservative impact planner. No new project/platform selector was introduced.

Certificates keep the original report, dependency snapshot and prior producer provenance alongside the current compatibility plan. Current test-result counts do not include inherited tests. A missing exact-baseline certificate or old certificate without sufficient input metadata leaves incomplete source coverage blocked. Full and periodic acceptance retain their actual execution obligations. This is source compatibility under recorded dependency inputs, not a claim that a package was newly restored or an example executed on the current runner.
