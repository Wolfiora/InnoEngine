# InnoEngine C# code style

This rulebook defines how handwritten C# in InnoEngine is named, laid out and written. It applies to every handwritten `.cs` file in the repository, including tests and tools. Third-party sources under `extern/`, generated files (`**/Generated/*.cs` and files carrying an `<auto-generated>` header) and the cases listed in [section 16](#16-exceptions) are out of scope.

The [coding rules](coding.md) own design, error-handling, resource and change-management requirements. This rulebook is the detailed authority for names and layout.

- Every rule has an ID such as `B-05`. Cite the ID in reviews and commit messages.
- Each rule states the requirement first, then shows a compliant example. A block introduced by **Avoid** shows what the rule forbids.
- "Must", "always" and "never" are requirements. "Prefer" and "recommended" describe the default; deviate only when the default hurts readability.
- External contracts take precedence over this rulebook: interface implementations, overrides, MSBuild task parameters, serialized names and native interop signatures keep the names their contract requires (see [section 16](#16-exceptions)).
- Formatting changes and renames are separate changes. A formatting-only change must not alter names, logic, execution order or public contracts. Renaming a public member is an API change.
- Automatic formatters must preserve these rules. Do not apply a formatter whose output differs from this rulebook.

## 1. Files and physical layout

### F-01 Encoding, line endings and indentation

- UTF-8 without a byte order mark.
- LF line endings.
- Four spaces per indentation level. Never use tab characters.
- No trailing whitespace.
- The file ends with exactly one newline.
- At most one consecutive blank line.

In the next two blocks `→` is a tab, `·` is a space and `¶` is a newline.

```text
····private int m_count;¶
}¶
```

Avoid (tab indentation, trailing whitespace, extra blank line at the end of the file):

```text
→private int m_count;··¶
}¶
¶
```

### F-02 One top-level type per file, named after the type

- The file name is the PascalCase name of its primary type: `EventDispatcher.cs` contains `EventDispatcher`.
- Generic arity is not part of the file name: `Pool<T>` lives in `Pool.cs`.
- Additional files of a `partial` type are named `Type.Part.cs`.
- A small, tightly coupled contract (an enum, delegate or parameter record used only by the primary type) may share the file. The primary type comes first.

```text
Inno.Core.Events/
    EventDispatcher.cs              class EventDispatcher
    EventDispatcher.Observation.cs  partial class EventDispatcher
    IEventSink.cs                   interface IEventSink
```

### F-03 File structure

A file contains, in this order: the using directives, one blank line, the file-scoped namespace, one blank line, the types. There is no file header comment, no license banner and no leading blank line.

```csharp
using System;
using System.Collections.Generic;

namespace Inno.Core.Events;

/// <summary>
/// Dispatches events to registered sinks.
/// </summary>
public sealed class EventDispatcher
{
    private readonly List<IEventSink> m_sinks = [];
}
```

Avoid (no blank line after the namespace):

```csharp
namespace Inno.Core.Events;
public sealed class EventDispatcher
{
    private readonly List<IEventSink> m_sinks = [];
}
```

### F-04 Line width

- Aim for 120 columns or fewer. 140 columns is the hard limit.
- Only an unsplittable string literal (a path, a URL, one diagnostic sentence) may exceed the hard limit.
- Do not split a name, a modifier list or a short expression body merely to shorten a line.

```csharp
// 107 columns: stays on one line.
public bool isMissing => m_source is null || !m_source.exists || m_source.generation != m_owner.generation;

// 145 columns on one line: break it by meaning.
throw new InvalidOperationException(
    $"The importer '{importer.name}' produced no result for '{path}' while generation {generation} was active."
);
```

Avoid (a short declaration split for no reason):

```csharp
public bool isMissing
    => m_source is null;
```

### F-05 Indentation and alignment of continuation lines

Prefer alignment over a fixed indent.

- **Operator continuation.** When an expression is broken at an operator (`&&`, `||`, `??`, `+`, `?`, `:`, `or`, `and`, …), each continuation line begins with the operator and aligns with the first operand of that expression.
- **Fallback.** When alignment would push a line past the hard limit, indent the continuation lines four spaces from the start of the statement instead.
- **Delimited lists.** The contents of a broken parameter list, argument list, initializer or collection are indented four spaces from the line that opens them. The closing delimiter, when it is on its own line, aligns with the first token of the opening line.
- **Call chains, wrapped `=>` and clauses.** A wrapped `.Member(...)` link, a wrapped expression-body `=>`, and a wrapped `where` or constructor-initializer clause are indented four spaces from the start of the statement or declaration.

```csharp
bool changed = previous.width != current.width
               || previous.height != current.height
               || previous.format != current.format;

return left.order != right.order
       || left.layer != right.layer;

string name = entry.displayName
              ?? entry.path.GetFileName()
              ?? string.Empty;

List<string> names = m_entries
    .Where(static entry => !entry.isMissing)
    .Select(static entry => entry.displayName)
    .ToList();
```

Avoid (operator continuation indented by a fixed amount instead of aligned):

```csharp
bool changed = previous.width != current.width
    || previous.height != current.height
    || previous.format != current.format;
```

## 2. Namespaces and using directives

### N-01 File-scoped namespaces

Use `namespace X;`. A file declares exactly one namespace.

```csharp
namespace Inno.Core.Events;

public sealed class EventDispatcher
{
    private int m_generation;
}
```

Avoid:

```csharp
namespace Inno.Core.Events
{
    public sealed class EventDispatcher
    {
        private int m_generation;
    }
}
```

### N-02 The namespace is the project name

The namespace starts with `Inno`, uses PascalCase segments and equals the assembly name of the owning project. Directories inside a project organize files; they do not add namespace segments.

```csharp
// File: src/content/assets/Inno.Assets.Pipeline/Importing/AssetLoader.cs
namespace Inno.Assets.Pipeline;
```

Avoid:

```csharp
// File: src/content/assets/Inno.Assets.Pipeline/Importing/AssetLoader.cs
namespace Inno.Assets.Pipeline.Importing;
```

The one registered exception is `Inno.Editor.ImGui/Widgets`, which uses `Inno.Editor.ImGui.ImGuiWidget`.

### N-03 Placement and kinds of using directives

- All using directives are at the top of the file, outside the namespace.
- `global using`, implicit usings and MSBuild `Using` items are prohibited. Handwritten code never uses `global::`.
- `using static` is reserved for pure function containers such as math helpers.

```csharp
using System;
using Inno.Core.Events;

namespace Inno.Rendering;
```

Avoid:

```csharp
global using System;

namespace Inno.Rendering;

using Inno.Core.Events;

public sealed class Renderer
{
    private readonly global::Inno.Core.Events.EventDispatcher m_dispatcher = new();
}
```

### N-04 Order of using directives

Using directives form up to three groups, in this order, separated by exactly one blank line:

1. Namespace usings.
2. `using static` directives.
3. Alias usings.

Inside the namespace group the order is:

1. `System` and `System.*`.
2. Everything else that is not `Inno` (third-party and framework packages).
3. `Inno` and `Inno.*`.

Each tier is sorted alphabetically (ordinal). There are no blank lines inside a group. Static usings follow the same three tiers; aliases are sorted by alias name.

```csharp
using System;
using System.Collections.Generic;
using System.Threading;
using Microsoft.CodeAnalysis;
using Xunit;
using Inno.Core.Events;
using Inno.Core.Identity;

using static System.MathF;

using AssetEvent = Inno.Assets.Pipeline.AssetChangedEvent;
using NativeWindow = Inno.Adapter.Platform.Sdl3.Sdl3Window;
```

Avoid (`Inno` before third-party namespaces, a blank line inside the namespace group, an alias among the namespace usings, no blank line between kinds):

```csharp
using Inno.Core.Events;
using AssetEvent = Inno.Assets.Pipeline.AssetChangedEvent;
using Xunit;

using System;
using System.Collections.Generic;
using static System.MathF;
```

### N-05 No fully qualified names at the point of use

Import a type with a using directive and refer to it by its short name. When two names collide, declare one alias at the top of the file and use only that alias throughout the file.

```csharp
using System.IO;

using AssetEvent = Inno.Assets.Pipeline.AssetChangedEvent;

namespace Inno.Assets.Pipeline.Tests;

public sealed class AssetLoaderTests
{
    private static AssetEvent Deleted(string path) => new(path, WatcherChangeTypes.Deleted);
}
```

Avoid:

```csharp
namespace Inno.Assets.Pipeline.Tests;

public sealed class AssetLoaderTests
{
    private static Inno.Assets.Pipeline.AssetChangedEvent Deleted(string path)
        => new(path, System.IO.WatcherChangeTypes.Deleted);
}
```

### N-06 Alias names

An alias is PascalCase, names the role the type plays in this file and differs from the short name of its target. One target has one alias per file.

```csharp
using NativeWindow = Inno.Adapter.Platform.Sdl3.Sdl3Window;
```

Avoid (the alias repeats the target name, and a second alias names the same target):

```csharp
using Sdl3Window = Inno.Adapter.Platform.Sdl3.Sdl3Window;
using Window = Inno.Adapter.Platform.Sdl3.Sdl3Window;
```

## 3. Naming

### Summary

| Element | Rule | Example |
| --- | --- | --- |
| Namespace segment | PascalCase | `Inno.Core.Events` |
| Class, struct, record, enum, delegate | PascalCase | `RenderGraph`, `AssetHandle` |
| Interface | `I` + PascalCase | `IEventSink` |
| Type parameter | `T` or `T` + PascalCase | `T`, `TSource` |
| Method, local function | PascalCase | `TryResolve`, `CreateBuffer` |
| Property, indexer | camelCase | `transform`, `isMissing` |
| Event | camelCase | `redrawRequested` |
| Constant (`const`, including local constants) | `C_` + UPPER_SNAKE | `C_MAX_COUNT` |
| `static readonly` field (any accessibility) | UPPER_SNAKE | `DEFAULT_OPTIONS`, `RED` |
| Private static mutable field | `s_` + camelCase | `s_nextID` |
| Private or protected instance field | `m_` + camelCase | `m_generation` |
| Internal or public instance field | camelCase | `latestSucceeded` |
| Enum member | PascalCase | `Borrowed` |
| Parameter, local variable, tuple element | camelCase | `outputDirectory` |
| Two-letter acronym | Upper case in PascalCase positions | `AssetID`, `IOStatus`, `UIScale` |
| Test class and test method | `XxxTests`, PascalCase sentence | `DispatchAfterDisposeThrows` |

### NM-01 Type names

A type name is a PascalCase noun or noun phrase. The suffix follows the role: `Attribute`, `Exception`, `EventArgs`, `Tests`, and `Extensions` for a class that holds extension methods. An abstract class has no `Base` or `Abstract` affix.

```csharp
public sealed class InspectorMessageAttribute : Attribute;

public static class PathExtensions
{
    public static string Normalize(this string path) => path.Replace('\\', '/');
}

public abstract class EditorDrop;
```

Avoid:

```csharp
public sealed class InspectorMessage : Attribute;

public static class PathHelpers
{
    public static string Normalize(this string path) => path.Replace('\\', '/');
}

public abstract class EditorDropBase;
```

### NM-02 Interfaces and type parameters

An interface name starts with `I`. No other type starts with `I` followed by an upper-case letter. Use `T` when there is a single, obvious type parameter; otherwise use `T` plus a description.

```csharp
public interface IAssetImporter<TAsset>
    where TAsset : class
{
    TAsset Import(string path);
}

public sealed class Pool<T>;
```

Avoid:

```csharp
public interface AssetImporter<Asset>
    where Asset : class
{
    Asset Import(string path);
}
```

### NM-03 Method names

A method name is PascalCase and starts with a verb. These prefixes have fixed meanings:

- `Try*` returns `bool`, does not throw on failure and returns its result through an `out` parameter.
- `Is*`, `Has*` and `Can*` return `bool` and have no side effects.
- `Create*` builds a new object that the caller owns.
- `Get*` reads existing state without side effects.
- `*Async` returns `Task` or `ValueTask` (NM-04).

```csharp
public bool TryResolve(
    AssetID id,
    out AssetHandle handle
) => m_handles.TryGetValue(id, out handle);
```

Avoid (`Try*` that does not return `bool`):

```csharp
public AssetHandle? TryResolve(AssetID id) => m_handles.GetValueOrDefault(id);
```

### NM-04 Asynchronous methods end with `Async`

A method that returns `Task`, `Task<T>`, `ValueTask` or `ValueTask<T>` ends with `Async`. Overrides and interface implementations follow their contract. xUnit test methods do not take the suffix.

```csharp
public async Task<ShaderCompilationResult> CompileAsync(
    ShaderSource source,
    CancellationToken cancellationToken
) {
    ShaderProgram program = await m_frontend.ParseAsync(source, cancellationToken).ConfigureAwait(false);
    return await m_backend.EmitAsync(program, cancellationToken).ConfigureAwait(false);
}
```

Avoid:

```csharp
public async Task<ShaderCompilationResult> Compile(
    ShaderSource source,
    CancellationToken cancellationToken
) {
    ShaderProgram program = await m_frontend.ParseAsync(source, cancellationToken).ConfigureAwait(false);
    return await m_backend.EmitAsync(program, cancellationToken).ConfigureAwait(false);
}
```

### NM-05 Properties and indexers are camelCase

Every property is camelCase, whatever its accessibility. A `bool` property starts with `is`, `has` or `can`, or is a past participle that states a condition, such as `disposed`.

```csharp
public Transform transform { get; }
public bool isMissing => m_source is null;
public int count { get; private set; }
```

Avoid:

```csharp
public Transform Transform { get; }
public bool Missing => m_source is null;
public int Count { get; private set; }
```

### NM-06 Instance fields

- A private or protected instance field is `m_` + camelCase, whether or not it is `readonly`.
- An internal or public instance field is camelCase without a prefix. Such fields appear only in frame-local workspaces, interop structs and math types.
- One declaration declares one field.

```csharp
public sealed class RenderQueue
{
    private readonly List<RenderItem> m_items = [];
    private int m_generation;
}

internal struct GlyphVertex
{
    public Vector2 position;
    public Vector2 uv;
}
```

Avoid:

```csharp
public sealed class RenderQueue
{
    private readonly List<RenderItem> _items = [];
    private int generation, frameIndex;
}
```

### NM-07 Constants

Every `const` is `C_` + UPPER_SNAKE: private, internal and public constants, and constants local to a method.

```csharp
public sealed class SceneFile
{
    public const string C_DEFAULT_EXTENSION = ".iscene";
    private const int C_MAX_COUNT = 64;

    public void Flush()
    {
        const int C_BATCH_SIZE = 256;
        Write(C_BATCH_SIZE);
    }
}
```

Avoid:

```csharp
public sealed class SceneFile
{
    public const string DefaultExtension = ".iscene";
    private const int MAX_COUNT = 64;

    public void Flush()
    {
        const int batchSize = 256;
        Write(batchSize);
    }
}
```

### NM-08 `static readonly` fields

Every `static readonly` field is UPPER_SNAKE without any prefix, whatever its accessibility. The `C_` prefix is reserved for `const`.

```csharp
public readonly struct Color
{
    public static readonly Color RED = FromBytes(255, 0, 0);
    private static readonly JsonSerializerOptions SERIALIZER_OPTIONS = new(JsonSerializerDefaults.Web);
}
```

Avoid:

```csharp
public readonly struct Color
{
    public static readonly Color Red = FromBytes(255, 0, 0);
    private static readonly JsonSerializerOptions S_SERIALIZER_OPTIONS = new();
    private static readonly JsonSerializerOptions s_serializerOptions = new();
    private static readonly JsonSerializerOptions C_SERIALIZER_OPTIONS = new();
}
```

### NM-09 Static mutable fields

A private static mutable field is `s_` + camelCase. Product code does not declare non-private static mutable fields; shared process state belongs to an explicit host.

```csharp
public sealed class HandleAllocator
{
    private static int s_nextID;
}
```

Avoid:

```csharp
public sealed class HandleAllocator
{
    private static int m_nextID;
    public static int nextID;
}
```

### NM-10 Events

An event is camelCase, like a property. Name it with a past participle or as `xxxChanged` / `xxxRequested`. Its delegate type is a nullable `Action` or `Action<...>`.

```csharp
public event Action? redrawRequested;
public event Action<AssetID>? assetReloaded;
```

Avoid:

```csharp
public event Action? RedrawRequested;
public event EventHandler? OnRedraw;
```

### NM-11 Enums

- A single-value enum has a singular name. A `[Flags]` enum has a plural name or ends with `Flags`.
- Members are PascalCase and never start with an underscore.
- `[Flags]` values are written as `1 << n`, with `None = 0`. Combined values are expressed with member names.
- One member per line, no trailing comma, no blank lines between members.

```csharp
public enum EditorPlayModeState
{
    Editing,
    Compiling,
    Playing
}

[Flags]
public enum EditorViewportNavigationCapabilities
{
    None = 0,
    Orbit = 1 << 0,
    Pan = 1 << 1,
    Zoom = 1 << 2,
    All = Orbit | Pan | Zoom
}
```

Avoid:

```csharp
[Flags]
public enum EditorViewportNavigationCapability
{
    None = 0,
    Orbit = 1,
    Pan = 0x2,
    Zoom = 4,
}
```

### NM-12 Parameters, local variables and tuple elements

Use camelCase and whole words. Do not use Hungarian prefixes. Do not give a local variable or a parameter the name of a property of the same type, except for constructor parameters (E-08).

| Situation | Name |
| --- | --- |
| `CancellationToken` parameter | `cancellationToken` |
| Default `catch` variable | `exception` |
| Unused lambda parameter | `_` |
| Loop index | `i`, `j`, `index` |
| Coordinate or component | `x`, `y`, `z`, `w` |

Apart from this table, do not use one- or two-character names. `id` and `io` are whole words and are allowed.

```csharp
public async Task SaveAsync(
    Stream destination,
    CancellationToken cancellationToken
) {
    (int width, int height) size = Measure();
    foreach (AssetEntry entry in m_entries)
    {
        await entry.WriteAsync(destination, size, cancellationToken).ConfigureAwait(false);
    }
}
```

Avoid:

```csharp
public async Task SaveAsync(
    Stream dst,
    CancellationToken token
) {
    (int Width, int Height) sz = Measure();
    foreach (AssetEntry e in m_entries)
    {
        await e.WriteAsync(dst, sz, token).ConfigureAwait(false);
    }
}
```

### NM-13 Acronyms

- A two-letter acronym is upper case wherever a PascalCase word would start: `ID`, `IO`, `UI`. This includes `ID`: write `AssetID`, `persistentID`, `GetID`, never `AssetId`.
- An acronym of three or more letters is written as an ordinary word: `Json`, `Http`, `Ktx`, `Sdl`.
- When an acronym starts a camelCase identifier, the whole acronym is lower case: `id`, `ioStatus`, `uiScale`.
- In UPPER_SNAKE names every word is upper case: `C_MAX_ID`.

```csharp
public sealed class JsonAssetWriter
{
    public AssetID persistentID { get; }
    public IOStatus ioStatus { get; }
    public float uiScale { get; set; }

    public AssetID GetID(string id) => m_ids[id];
}
```

Avoid:

```csharp
public sealed class JSONAssetWriter
{
    public AssetId persistentId { get; }
    public IoStatus IOStatus { get; }
    public float UIScale { get; set; }

    public AssetId GetId(string ID) => m_ids[ID];
}
```

## 4. Type declarations

### T-01 Write every access modifier

Every type and every member states its accessibility, including each file of a `partial` type. Interface members do not write `public`.

```csharp
internal sealed partial class AssetLoader
{
    private int m_generation;
}

public interface IEventSink
{
    void Publish(EventRecord record);
}
```

Avoid:

```csharp
sealed partial class AssetLoader
{
    int m_generation;
}
```

### T-02 Modifier order

Accessibility, then `static`, `extern`, `new`, then `virtual` / `abstract` / `sealed` / `override`, then `readonly`, `unsafe`, `required`, `volatile`, `async`, `partial`.

```csharp
public static readonly Color RED = FromBytes(255, 0, 0);

private static async Task RunAsync()
{
    await Task.Yield();
    Publish();
}

public sealed override string ToString() => name;

public override readonly int GetHashCode() => m_value;

internal static unsafe partial class NativeMethods;
```

Avoid:

```csharp
public readonly override int GetHashCode() => m_value;

static private int s_count;
```

### T-03 Classes are sealed by default

Every class is `static`, `abstract` or `sealed`. Leave a class open only when it is a designed extension point, and document the derivation contract in its XML documentation. Nested private classes are sealed too.

```csharp
public sealed class EventDispatcher;

internal static class PathUtility
{
    internal static string Normalize(string path) => path.Replace('\\', '/');
}

public abstract class EditorDrop;
```

Avoid:

```csharp
public class EventDispatcher;
```

### T-04 Records

- A reference-type data contract is a `sealed record` with positional parameters, ending in `;`.
- A small value type is a `readonly record struct`.
- Positional parameters are properties, so they are camelCase.

```csharp
public sealed record AssetChangedEvent(
    string path,
    WatcherChangeTypes change
);

public readonly record struct AssetID(Guid value);
```

Avoid:

```csharp
public record AssetChangedEvent(string Path, WatcherChangeTypes Change);

public record struct AssetID(Guid value);
```

### T-05 Structs

A struct is `readonly` by default. Use a mutable struct only for interop layouts and math types that are assigned field by field; its fields are public and camelCase.

```csharp
public readonly struct FrameRange
{
    public int start { get; }
    public int count { get; }
}

[StructLayout(LayoutKind.Sequential)]
internal struct GlyphVertex
{
    public Vector2 position;
    public Vector2 uv;
}
```

Avoid (a mutable struct that is not an interop or math type):

```csharp
public struct FrameRange
{
    public int start { get; set; }
    public int count { get; set; }
}
```

### T-06 Base lists and generic constraints on types

- The base list stays on the line of the type name.
- Each `where` clause of a type is on its own line, indented four spaces. The opening brace stays on its own line.

```csharp
public abstract class EditorDrop<TSource, TTarget> : EditorDrop
    where TSource : IdentityObject
    where TTarget : class
{
    public abstract bool Accepts(TSource source);
}
```

Avoid:

```csharp
public abstract class EditorDrop<TSource, TTarget>
    : EditorDrop where TSource : IdentityObject where TTarget : class
{
    public abstract bool Accepts(TSource source);
}
```

### T-07 Primary constructors

- A record always uses a primary constructor.
- A class or struct may use a primary constructor to receive its dependencies. When it does, it uses the parameters directly and does not copy them into `m_` fields.
- Use an ordinary constructor with `m_` fields when arguments need validation or the fields must be `readonly`.
- Primary constructor parameters follow P-01. A base list follows the closing parenthesis as `) : Base`, with the opening brace on its own line. Without a base list the type body starts with `) {`.

```csharp
internal sealed class TogglePlayModeAction(EditorPlayMode playMode) : EditorAction
{
    protected override bool CanExecute() => playMode.state != EditorPlayModeState.Compiling;
}

internal sealed class SceneReloadChange(
    RuntimeSession runtimeSession,
    ISceneReloadStateTransfer migration
) : IGenerationChange
{
    public void Apply() => migration.Transfer(runtimeSession);
}

internal sealed class FrameScope(
    RenderGraph graph,
    int frameIndex
) {
    public bool isFirst => frameIndex == 0;

    public void Begin() => graph.BeginFrame(frameIndex);
}
```

Avoid (base list on a separate line, parameters copied into fields):

```csharp
internal sealed class SceneReloadChange(
    RuntimeSession runtimeSession,
    ISceneReloadStateTransfer migration
)
    : IGenerationChange
{
    private readonly RuntimeSession m_runtimeSession = runtimeSession;
    private readonly ISceneReloadStateTransfer m_migration = migration;
}
```

### T-08 Nested types

A nested type is placed at the end of its containing type. Nest a type only when the containing type is its only user.

```csharp
public sealed class AssetCache
{
    private readonly Dictionary<AssetID, Entry> m_entries = [];

    public int count => m_entries.Count;

    private sealed class Entry
    {
        public AssetHandle handle { get; init; }
        public int generation { get; set; }
    }
}
```

Avoid (the nested type comes first):

```csharp
public sealed class AssetCache
{
    private sealed class Entry
    {
        public AssetHandle handle { get; init; }
        public int generation { get; set; }
    }

    private readonly Dictionary<AssetID, Entry> m_entries = [];
}
```

## 5. Member declarations

### M-01 Property forms

- An auto-property is written on one line: `{ get; }`, `{ get; set; }`, `{ get; init; }`, `{ get; private set; }`.
- A read-only computed property uses an expression body.
- A property whose accessors contain logic is expanded: the braces are on their own lines, an accessor with a single expression uses `=>`, an accessor with statements uses a block.

```csharp
public string name { get; }
public int count { get; private set; }
public bool isEmpty => m_items.Count == 0;

public float scale
{
    get => m_scale;
    set
```

### M-03 Placement of `=>` in expression-bodied members

1. When the whole member fits on one line, `=> expression` stays on the declaration line.
2. After a multi-line parameter list, the body starts on the line of the closing parenthesis: `) => expression`. When the expression is a call, an object creation or a collection that does not fit, break inside it (A-02).

5. After a wrapped `=>`, a call or object creation that must break follows A-02 relative to the `=>` line, and operator continuation lines align with the first operand (F-05).

## 6. Member order

### O-01 Group order

Members of a type appear in these groups, in this order, with one blank line between groups:

1. Constants (`const`).
2. Static fields: `static readonly` first, then static mutable.
3. Instance fields: `readonly` first, then mutable.
4. Constructors.
5. Public members.
6. Protected and internal members.
7. Private members.
8. Nested types.

Inside groups 5, 6 and 7 the order is: properties, events, instance methods, static methods. An explicit interface implementation follows the public members of the interface it implements.

```csharp
public sealed class RenderQueue : IDisposable
{
    private const int C_INITIAL_CAPACITY = 64;

    private static readonly RenderItemComparer COMPARER = new();

    private readonly List<RenderItem> m_items;
    private bool m_disposed;

    public RenderQueue()
    {
        m_items = new List<RenderItem>(C_INITIAL_CAPACITY);
    }

    public int count => m_items.Count;

    public event Action? flushed;

    public void Enqueue(RenderItem item)
    {
        ObjectDisposedException.ThrowIf(m_disposed, this);
        m_items.Add(item);
    }

    public void Dispose()
    {
        m_items.Clear();
        m_disposed = true;
    }

    internal void Sort() => m_items.Sort(COMPARER);

    private void NotifyFlushed() => flushed?.Invoke();

    private sealed class RenderItemComparer : IComparer<RenderItem>
    {
        public int Compare(
            RenderItem left,
            RenderItem right
        ) => left.order.CompareTo(right.order);
    }
}
```

Avoid (a private method before the public members, fields after the constructor):


## 7. Braces and blocks

### B-01 Braces are on their own lines

The opening brace of a type, a method body, an accessor, a control statement, a lambda block, an object or collection initializer and a `switch` expression is on its own line, aligned with the start of the construct. The closing brace is on its own line, aligned with the opening brace.

The only places where an opening brace shares a line with other code are:

- `) {` after a multi-line parameter list or a multi-line statement header (B-02).
- A single-line construct: an auto-property, a short initializer, a property pattern, a compact guard (B-05).
- An empty body `{}` (B-07).

```csharp

        m_drawn++;

    try
```

### B-02 `) {` after a multi-line parameter list or statement header

When a parameter list is expanded over several lines (P-01) and the body follows it directly, the opening brace shares the line of the closing parenthesis: `) {`. The closing brace aligns with the start of the declaration. This applies to methods, constructors, local functions, operators and primary constructors without a base list. The same form closes a control statement whose header spans several lines (W-05).

### B-03 Clauses between `)` and the body

A constructor initializer (`: base(...)`, `: this(...)`) or a `where` clause sits between the parameter list and the body.

- After a multi-line parameter list, the clause follows the closing parenthesis on the same line: `) : this(...)` or `) where T : class`. The opening brace is then on its own line.
- After a single-line signature, the clause is on the next line, indented four spaces. The opening brace is on its own line.
- Additional `where` clauses each take their own line, aligned with the first `where`.

### B-04 Lambda bodies

- **Expression body that fits:** `x => expression` on one line.
- **Block body:** `=>` ends the line; the braces are on their own lines, aligned with the start of the statement that contains the lambda. The closing brace is followed directly by `)`, `,` or `;`. This holds when the lambda has a multi-line parameter list too: `) =>`, then the brace on the next line.
- **Expression body that is a call or object creation and does not fit:** the call starts on the `=>` line and breaks inside its parentheses (A-02).
- **Any other expression body that does not fit:** wrap it in parentheses. `(` follows `=>`, the expression is indented four spaces, and `)` is on its own line.

### B-05 Control statement bodies always use braces

4. Stacked `using` or `fixed` headers that share one braced body are the only headers that may follow each other without braces in between.

### I-01 Object initializers

- A short initializer stays on one line with one space inside each brace: `new Foo { a = 1 }`.

- Omit the empty `()` when an initializer is present.
- `with` expressions and anonymous objects follow the same rule.

- A spread operator is followed by one space: `[.. source, extra]`.

- Do not write `new[] { ... }`, `new T[] { ... }`, `new List<T> { ... }` or `Array.Empty<T>()`.


- A single element that itself spans several lines hugs the brackets: `[new X(` … `)]`.

## 11. Spacing and blank lines

### S-01 Spaces

| Position | Rule | Example |
| --- | --- | --- |
| Control keyword and `(` | One space | `if (x)`, `foreach (T item in items)` |
| Method name, `typeof`, `nameof`, `default` and `(` | No space | `Draw(item)`, `typeof(int)` |
| `new` and `(` or `[` | No space | `new()`, `new[]` |
| Inside parentheses and brackets | No space | `Add(a, b)`, `items[0]` |
| Before an index bracket | No space | `items[0]` |
| Comma | None before, one after | `Add(a, b)` |
| Semicolon in `for` | None before, one after | `for (int i = 0; i < n; i++)` |
| Binary operators, assignment, `=>`, `??`, `?:` | One on each side | `a + b`, `x => x.id` |
| Unary operators | Attached to the operand | `!ready`, `-value`, `i++` |
| After a cast | No space | `(float)count` |
| Member access `.`, `?.`, `->` | No space | `entry?.name` |
| Inside generic angle brackets | No space | `Dictionary<string, int>` |
| Nullable `?` and pointer `*` | Attached to the type | `string?`, `byte* data` |
| Range `..` | No space | `span[1..^1]` |
| Spread `..` | One space after | `[.. items]` |
| Inside single-line braces with content | One on each side | `{ get; }`, `new T { a = 1 }`, `is { }` |
| Empty body | No space inside | `{}` |
| Before `{` on the same line | One space | `) {`, `() {}` |
| Colon of a base list, constraint or initializer | One on each side | `class A : B`, `where T : class` |
| Colon of a named argument or attribute target | None before, one after | `width: 1280`, `[assembly: X]` |

```csharp
if (ready)
{
    float ratio = (float)count / total;
    int first = items[0];
    Draw(item, ratio, first);
}
```

Avoid:

```csharp
if(ready)
{
    float ratio = (float) count/total;
    int first = items [0];
    Draw( item,ratio , first );
}
```

### S-02 Column alignment

- When more than three consecutive `const` declarations, or more than three consecutive `static readonly` declarations, have the same type, aligning their `=` signs in a column is recommended. It is not required.
- A numeric matrix or lookup table may align its elements in columns.
- Everywhere else, use a single space between tokens. Do not column-align local variables, assignments, parameters or comments.

```csharp

private const int C_REFRESH_RATE = 60;

    1f, 0f, 0f, 0f,
    0f, 1f, 0f, 0f,
    0f, 0f, 1f, 0f,
    0f, 0f, 0f, 1f

```

Avoid (alignment of local variables and trailing comments):


### S-04 Blank lines inside method bodies

- The argument validation at the start of a method (a run of `ThrowIf*` calls and guards) is contiguous and followed by one blank line.

## 12. Types and expression idioms

### E-01 Local variables state their type; `var` only with `new T(...)`

- A local variable declares its type: `T x = expression;`.
- Use `var` when the right-hand side is `new T(...)` or `new T[...]`, where the type is visible on the same line.
- An anonymous type requires `var`.
- A local variable does not use `T x = new(...)`; that form is for fields and properties (M-04).

### E-06 Object creation

- A local variable: `var x = new T(...)` (E-01).
- A field or property initializer: `= new(...)` (M-04).
- A member that directly returns a new object of its declared return type may use `new(...)`.
- An argument, or a creation inside a larger expression, writes the type: `new T(...)`.


### E-07 Common values

| --- | --- | --- |

### E-08 `this.`

- Inside a constructor, every assignment to an instance member that is not an `m_` field goes through `this.`: `this.name = name;`, `this.count = 0;`. This holds whether or not a parameter has the same name.
- Outside constructors, do not write `this.` unless it is needed to disambiguate.
- Apart from constructor parameters, a parameter or local variable does not take the name of a property of the same type.

### E-09 Strings

- Build strings from values with interpolation, `$"..."`. Do not use `string.Format` or `string.Concat`.
- Split a long message with `+` at the start of the continuation line (W-01). Use a raw string literal, `"""`, for multi-line text.
- Comparison, lookup, sorting and dictionaries state `StringComparison.Ordinal` / `StringComparer.Ordinal` or the `OrdinalIgnoreCase` variants.
- Change case with `ToLowerInvariant()` / `ToUpperInvariant()` and format with `CultureInfo.InvariantCulture`.
- Refer to identifiers with `nameof(...)`.
- Test external input with `string.IsNullOrWhiteSpace`, and use `string.IsNullOrEmpty` only when whitespace is meaningful.

### E-10 Numeric literals

- `float`: write an integral value as `1f` and a fractional value as `1.5f`. Do not write `1.0f` or `1.50f`.
- Suffixes: `f`, `d`, `m` and `u` are lower case; `L` and `UL` are upper case.
- Hexadecimal: the `0x` prefix is lower case, the digits are upper case, and long values are grouped by four digits with `_`.
- Large decimal values are grouped by three digits with `_`.

- One parameter has no parentheses: `x => ...`. No parameters: `() => ...`. Two or more parameters are expanded (P-01).
- Parameters have meaningful names. An unused parameter is `_`.
- A lambda that captures neither a local variable nor `this` is `static`.
- A single-expression body uses the expression form; several statements use a block (B-04).
- When an expression body does not fit on the line of the lambda, it is wrapped in parentheses, unless it is a call or object creation, which breaks inside its own parentheses (B-04).

## 13. Control flow, exceptions and asynchronous code

### X-01 Guard clauses return early

### X-02 `switch`

### X-03 Exception types and messages

| --- | --- |

| The object has been disposed | `ObjectDisposedException`, through `ThrowIf` |
| Input data is malformed | `InvalidDataException` |
| The platform or backend does not support the operation | `NotSupportedException` |

A message is a complete English sentence that includes the offending value. Parameter names use `nameof`. A `throw` whose arguments do not fit on one line breaks like any other call (A-02).

```csharp
throw new InvalidDataException(
    $"The scene file '{path}' declares version {version}, but only version {C_VERSION} is supported."
);
```

Avoid:

```csharp
throw new InvalidDataException(
    $"The scene file '{path}' declares version {version}, but only version {C_VERSION} is supported.");

throw new Exception("bad version");
```

### X-04 `catch`

- Catch the specific type that can be handled. When catching `Exception`, filter with `when` or rethrow with `throw;` after handling.
- The variable is named `exception` by default. A name that states the role, such as `cleanupFailure`, is allowed when the exception is stored or aggregated. Omit the variable when it is not used.
- A bare `catch` without a type is only for "clean up, then rethrow".
- A `catch` block that deliberately ignores an exception contains a comment that says why.

```csharp
try
{
    Directory.Delete(scratch, recursive: true);
}
catch (IOException)
{
    // The scratch directory is retried by the next retirement pass.
}

try
{
    Publish(candidate);
}
catch (Exception exception) when (exception is not OperationCanceledException)
{
    m_log.Error($"Publication failed: {exception.Message}");
    throw;
}
```

Avoid:

```csharp
try
{
    Directory.Delete(scratch, recursive: true);
}
catch {}

try
{
    Publish(candidate);
}
catch (Exception ex)
{
    throw ex;
}
```

### X-05 Asynchronous code

- Return `Task` or `ValueTask`. Never write `async void`.
- The method name ends with `Async` (NM-04). `CancellationToken cancellationToken` is the last parameter and is passed down to every asynchronous call.
- In product code (`src`, `build`, `backends`, `platforms`, `tools`, `entry`) every `await` ends with `.ConfigureAwait(false)`. Test code does not use `ConfigureAwait`.
- Do not block on asynchronous results with `.Wait()`, `.Result` or `.GetAwaiter().GetResult()`. An entry point that must wait synchronously carries a comment that explains why.
- On a broken `await` call, `.ConfigureAwait(false)` follows the closing parenthesis on its line.

```csharp
public async Task<AssetHandle> LoadAsync(
    AssetID id,
    CancellationToken cancellationToken
) {
    await using Stream stream = await m_storage.OpenAsync(id, cancellationToken).ConfigureAwait(false);
    return await m_reader.ReadAsync(
        stream,
        id,
        cancellationToken
    ).ConfigureAwait(false);
}
```

Avoid:

```csharp
public async void Load(AssetID id)
{
    Stream stream = m_storage.OpenAsync(id, CancellationToken.None).Result;
    await m_reader.ReadAsync(stream, id, CancellationToken.None);
}
```

## 14. Comments and XML documentation

### D-01 Which members need XML documentation

Every externally visible public member, and every protected member that an external type can override, has complete English XML documentation. Important internal APIs are documented as well. Private members and test code do not need documentation.

```csharp
/// <summary>
/// Stores render items until the next flush.
/// </summary>
public sealed class RenderQueue
{
    private readonly List<RenderItem> m_items = [];

    /// <summary>
    /// Gets the number of queued items.
    /// </summary>
    public int count => m_items.Count;

    private void Trim() => m_items.TrimExcess();
}
```

Avoid (a public type and a public property without documentation):

```csharp
public sealed class RenderQueue
{
    public int count => m_items.Count;
}
```

### D-02 Tags are expanded, one element per block

- The start tag, the content and the end tag are on separate lines. `///` is followed by one space. A documentation block has no empty `///` lines.
- Tag order: `summary`, `typeparam`, `param` (in signature order), `returns`, `exception`, `remarks`.
- Every content block starts with a capital letter and ends with a period.
- Wrap long content at complete semantic boundaries.

```csharp
/// <summary>
/// Resolves a loaded asset by its persistent identity.
/// </summary>
/// <typeparam name="TAsset">
/// The asset type expected by the caller.
/// </typeparam>
/// <param name="id">
/// The persistent identity of the asset.
/// </param>
/// <param name="asset">
/// Receives the asset when this method returns <see langword="true"/>;
/// otherwise <see langword="null"/>.
/// </param>
/// <returns>
/// <see langword="true"/> when the asset is loaded and has the requested type;
/// otherwise <see langword="false"/>.
/// </returns>
/// <exception cref="ObjectDisposedException">
/// The loader has been disposed.
/// </exception>
public bool TryResolve<TAsset>(
    AssetID id,
    [NotNullWhen(true)] out TAsset? asset
) where TAsset : class
{
    ObjectDisposedException.ThrowIf(m_disposed, this);
    return TryResolveCore(id, out asset);
}
```

Avoid:

```csharp
/// <summary>Resolves an asset</summary>
/// <param name="asset">the asset</param>
/// <param name="id">the id</param>
/// <returns>true if found</returns>
public bool TryResolve<TAsset>(
    AssetID id,
    [NotNullWhen(true)] out TAsset? asset
) where TAsset : class
{
    ObjectDisposedException.ThrowIf(m_disposed, this);
    return TryResolveCore(id, out asset);
}
```

### D-03 Wording of summaries

| Member | Starts with | Example |
| --- | --- | --- |
| Read-only property | `Gets` | `Gets the current width in pixels.` |
| Writable property | `Gets or sets` | `Gets or sets the clear color.` |
| `bool` property | `Gets a value indicating whether` | `Gets a value indicating whether the asset is missing.` |
| Method | A third-person verb | `Creates`, `Releases`, `Determines whether`, `Attempts to` |
| Constructor | `Initializes a new instance of` or `Creates` | `Creates a dispatcher bound to the given hub.` |
| Type | A third-person verb or a noun phrase | `Identifies`, `Describes`, `Provides`, `Represents` |
| Event | `Occurs when` | `Occurs when the platform requests a redraw.` |

A summary describes real behavior. It does not restate the member name.

```csharp
/// <summary>
/// Gets the current width of the viewport in pixels.
/// </summary>
public int width => m_width;
```

Avoid:

```csharp
/// <summary>
/// The width.
/// </summary>
public int width => m_width;
```

### D-04 References inside documentation

- A type or member: `<see cref="AssetLoader"/>`. A parameter: `<paramref name="id"/>`. A type parameter: `<typeparamref name="TAsset"/>`.
- A keyword: `<see langword="null"/>`, `<see langword="true"/>`, `<see langword="false"/>`.
- A self-closing tag has no space before `/>`.
- An override or interface implementation uses `/// <inheritdoc/>` and documents any additional constraint locally with `remarks` or `exception`.

```csharp
/// <inheritdoc/>
public override string ToString() => name;
```

Avoid:

```csharp
/// <summary>
/// Returns null if id is not found. See AssetLoader.
/// </summary>
/// <inheritdoc />
public override string ToString() => name;
```

### D-05 `//` comments

- A comment explains a reason, a constraint, ownership or a lifetime. It does not restate the code.
- A comment is on its own line, above the code it explains, at the indentation of that code. Do not write trailing comments.
- `//` is followed by one space. The comment is a complete English sentence that starts with a capital letter and ends with a period.

```csharp
// The native window must outlive the swap chain, so it is released last.
m_swapChain.Dispose();
m_window.Dispose();
```

Avoid:

```csharp
m_swapChain.Dispose(); // dispose swap chain
//release window
m_window.Dispose();
```

### D-06 Prohibited comments and directives

- Comments in any language other than English.
- `TODO`, `FIXME` or `HACK` markers left in place indefinitely.
- Commented-out code.
- Separator lines, banner comments and `/* */` block comments.
- `#region` and `#endregion`.
- `#nullable` inside a file, and `#pragma warning disable` without a comment that states the reason.

`#if`, `#elif`, `#else` and `#endif` start at column 0. Conditional symbols are UPPER_SNAKE with the `INNO_` prefix, except `DEBUG`.

```csharp
#if INNO_HOST_WINDOWS_X64
    private const string C_LIBRARY_NAME = "bgfx.dll";
#elif INNO_HOST_MACOS_ARM64
    private const string C_LIBRARY_NAME = "libbgfx.dylib";
#endif
```

Avoid:

```csharp
#region Constants
    // ---------- library ----------
    // TODO: revisit
    // private const string C_OLD_NAME = "bgfx_old.dll";
    private const string C_LIBRARY_NAME = "bgfx.dll"; /* windows */
#endregion
```

## 15. Tests

### TS-01 Structure

- Tests use xUnit. A test class is `public sealed class XxxTests` in `XxxTests.cs`, in the namespace of the test project.
- A test method is `public`, returns `void` or `async Task`, and carries `[Fact]`, or `[Theory]` with `[InlineData]`.
- Test classes and test methods do not need XML documentation.
- Fixtures and test doubles follow the same naming and layout rules as product code. A nested test double is `private sealed` and placed at the end of the test class.

```csharp
using System;
using Xunit;
using Inno.Core.Events;

namespace Inno.Core.Events.Tests;

public sealed class EventDispatcherTests
{
    [Fact]
    public void NewDispatcherHasNoSinks()
    {
        var dispatcher = new EventDispatcher();

        Assert.Empty(dispatcher.sinks);
    }

    private sealed class RecordingSink : IEventSink
    {
        public int published { get; private set; }

        public void Publish(EventRecord record) => published++;
    }
}
```

Avoid:

```csharp
public class EventDispatcherTest
{
    [Fact]
    void NewDispatcherHasNoSinks() {}
}
```

### TS-02 Test method names

A test method name is a PascalCase statement of what happens under which condition. It has no underscores, no `Async` suffix and no `Test` prefix or suffix.

```csharp
public sealed class EventDispatcherTests
{
    [Fact]
    public void DispatchAfterDisposeThrowsObjectDisposedException()
    {
        var dispatcher = new EventDispatcher();
        dispatcher.Dispose();

        Assert.Throws<ObjectDisposedException>(() => dispatcher.Dispatch(new EventRecord()));
    }

    [Theory]
    [InlineData(0)]
    [InlineData(-1)]
    public void NonPositiveCapacityIsRejected(int capacity)
        => Assert.Throws<ArgumentOutOfRangeException>(() => new EventDispatcher(capacity));

    [Fact]
    public async Task PendingEventsAreDeliveredBeforeShutdownCompletes()
    {
        var dispatcher = new EventDispatcher();
        List<EventRecord> received = [];
        dispatcher.dispatched += received.Add;

        dispatcher.Dispatch(new EventRecord());
        await dispatcher.ShutdownAsync(CancellationToken.None);

        Assert.Single(received);
    }
}
```

Avoid:

```csharp
public sealed class EventDispatcherTests
{
    [Fact]
    public void Dispatch_AfterDispose_Throws()
    {
        var dispatcher = new EventDispatcher();
        dispatcher.Dispose();
    }

    [Fact]
    public async Task TestShutdownAsync()
    {
        var dispatcher = new EventDispatcher();
        await dispatcher.ShutdownAsync(CancellationToken.None).ConfigureAwait(false);
    }
}
```

### TS-03 Assertions and layout

- Separate the arrange, act and assert phases with one blank line. A very short test may omit the separation.
- `Assert.Equal(expected, actual)`: the expected value comes first.
- Source text used as test data (generator inputs and expected outputs) is data, not code; this rulebook does not apply to it.

```csharp
[Fact]
public void ResizeUpdatesBothDimensions()
{
    var viewport = new Viewport(m_target, "Main", 640);

    viewport.Resize(width: 1280, height: 720);

    Assert.Equal(1280, viewport.width);
    Assert.Equal(720, viewport.height);
}
```

Avoid (actual value first, phases not separated):

```csharp
[Fact]
public void ResizeUpdatesBothDimensions()
{
    var viewport = new Viewport(m_target, "Main", 640);
    viewport.Resize(width: 1280, height: 720);
    Assert.Equal(viewport.width, 1280);
}
```

## 16. Exceptions

The following cases follow an external contract. Do not rename or reformat them to satisfy this rulebook.

| Case | What it keeps | Example |
| --- | --- | --- |
| Generated code and third-party sources | Everything | `extern/`, `**/Generated/*.cs`, `<auto-generated>` files |
| MSBuild task parameters | PascalCase property names bound by MSBuild | `public string OutputPath { get; set; }` |
| Overrides and interface implementations | The name declared by the base type or interface | `Stream.CanRead`, `IEnumerator.Current` |
| Special CLR members | Names required by the language or runtime | operators, `GetEnumerator`, `Deconstruct`, `Dispose` |
| Native interop signatures | Field names, enum values and imported function names from the native header | `SDL_Event`, bgfx enums |
| Serialized wire names | The serialized name; source property names and wire names are declared separately | |
| Third-party product names | The spelling used by the product | `RmlUi`, `ImGui`, `MiniAudio` |
| Keyboard and input code enums | Single-letter and digit members | `KeyCode.A`, `KeyCode.F1` |
| Numeric matrices and lookup tables | Several elements per line, column alignment (S-02) | a 4×4 matrix literal |
| Unsplittable string literals | Length beyond the line width (F-04) | paths, URLs |
| Generator templates and their tests | `global::` and fully qualified names required by the generation protocol | |
| Source text used as test data | Its own formatting (TS-03) | |

Keep each exception as small as possible: it covers the name or the layout bound by the contract, and the rest of the file follows the rulebook.

## 17. Reference example

One file that applies the rules together.

```csharp
using System;
using System.Collections.Generic;
using System.Diagnostics.CodeAnalysis;
using System.IO;
using System.Threading;
using System.Threading.Tasks;
using Inno.Core.Diagnostics;
using Inno.Core.Identity;

using AssetEvent = Inno.Assets.Pipeline.AssetChangedEvent;

namespace Inno.Assets.Pipeline;

/// <summary>
/// Caches loaded assets and reloads them when their sources change.
/// </summary>
public sealed class AssetCache : IDisposable
{
    private const int C_INITIAL_CAPACITY = 64;
    private const int C_MAX_ATTEMPT_COUNT = 3;

    private static readonly TimeSpan RETRY_DELAY = TimeSpan.FromMilliseconds(50);

    private readonly Dictionary<AssetID, Entry> m_entries = new(C_INITIAL_CAPACITY);
    private readonly IAssetStore m_store;
    private readonly ILogSink m_log;
    private int m_generation;
    private bool m_disposed;

    /// <summary>
    /// Creates a cache that reads asset content from the given store.
    /// </summary>
    /// <param name="store">
    /// The store that provides asset content.
    /// </param>
    /// <param name="log">
    /// The sink that receives reload diagnostics.
    /// </param>
    /// <param name="name">
    /// The diagnostic name of the cache.
    /// </param>
    /// <exception cref="ArgumentException">
    /// <paramref name="name"/> is empty or consists only of white space.
    /// </exception>
    public AssetCache(
        IAssetStore store,
        ILogSink log,
        string name
    ) {
        ArgumentNullException.ThrowIfNull(store);
        ArgumentNullException.ThrowIfNull(log);
        ArgumentException.ThrowIfNullOrWhiteSpace(name);

        m_store = store;
        m_log = log;
        this.name = name;
        this.isEnabled = true;
    }

    /// <summary>
    /// Gets the diagnostic name of the cache.
    /// </summary>
    public string name { get; }

    /// <summary>
    /// Gets a value indicating whether the cache accepts source changes.
    /// </summary>
    public bool isEnabled { get; private set; }

    /// <summary>
    /// Gets the number of cached assets.
    /// </summary>
    public int count => m_entries.Count;

    /// <summary>
    /// Occurs when a cached asset has been reloaded from its source.
    /// </summary>
    public event Action<AssetID>? assetReloaded;

    /// <summary>
    /// Attempts to find a cached asset that is still current.
    /// </summary>
    /// <param name="id">
    /// The persistent identity of the asset.
    /// </param>
    /// <param name="handle">
    /// Receives the cached handle when this method returns <see langword="true"/>;
    /// otherwise <see langword="null"/>.
    /// </param>
    /// <returns>
    /// <see langword="true"/> when a current entry exists; otherwise <see langword="false"/>.
    /// </returns>
    public bool TryResolve(
        AssetID id,
        [NotNullWhen(true)] out AssetHandle? handle
    ) {
        ObjectDisposedException.ThrowIf(m_disposed, this);

        if (m_entries.TryGetValue(id, out Entry? entry)
            && entry.generation == m_generation
            && !entry.handle.isMissing
        ) {
            handle = entry.handle;
            return true;
        }

        handle = null;
        return false;
    }

    /// <summary>
    /// Loads an asset, reusing the cached handle when it is still current.
    /// </summary>
    /// <param name="id">
    /// The persistent identity of the asset.
    /// </param>
    /// <param name="cancellationToken">
    /// A token that cancels the load.
    /// </param>
    /// <returns>
    /// The loaded asset handle.
    /// </returns>
    /// <exception cref="InvalidDataException">
    /// The store could not provide the asset after every attempt.
    /// </exception>
    public async Task<AssetHandle> LoadAsync(
        AssetID id,
        CancellationToken cancellationToken
    ) {
        if (TryResolve(id, out AssetHandle? cached)) return cached;

        for (int attempt = 1; attempt <= C_MAX_ATTEMPT_COUNT; attempt++)
        {
            try
            {
                AssetHandle handle = await m_store.LoadAsync(id, cancellationToken).ConfigureAwait(false);
                m_entries[id] = new Entry(handle, m_generation);
                return handle;
            }
            catch (IOException exception) when (attempt < C_MAX_ATTEMPT_COUNT)
            {
                m_log.Warning($"Loading asset '{id}' failed on attempt {attempt}: {exception.Message}");
                await Task.Delay(RETRY_DELAY, cancellationToken).ConfigureAwait(false);
            }
        }

        throw new InvalidDataException(
            $"The asset '{id}' could not be loaded from store '{m_store.name}' after {C_MAX_ATTEMPT_COUNT} attempts."
        );
    }

    /// <summary>
    /// Applies source changes and invalidates the affected entries.
    /// </summary>
    /// <param name="changes">
    /// The source changes reported by the watcher.
    /// </param>
    public void ApplySourceChanges(IReadOnlyList<AssetEvent> changes)
    {
        ArgumentNullException.ThrowIfNull(changes);
        if (!isEnabled) return;

        m_generation++;
        foreach (AssetEvent change in changes)
        {
            if (!m_store.TryGetID(change.path, out AssetID id)) continue;

            string action = change.change switch
            {
                WatcherChangeTypes.Deleted => "removed",
                WatcherChangeTypes.Renamed => "renamed",
                _ => "changed"
            };
            m_log.Info($"Asset '{id}' was {action}.");

            m_entries.Remove(id);
            assetReloaded?.Invoke(id);
        }
    }

    /// <inheritdoc/>
    public void Dispose()
    {
        if (m_disposed) return;

        // Entries only borrow their handles, so the store releases the content.
        m_entries.Clear();
        m_disposed = true;
    }

    internal bool IsCurrent(AssetID id)
        => m_entries.TryGetValue(id, out Entry? entry)
           && entry.generation == m_generation;

    private sealed record Entry(
        AssetHandle handle,
        int generation
    );
}
```
