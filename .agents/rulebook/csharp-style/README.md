# InnoEngine C# code style

This rulebook defines how handwritten C# in InnoEngine is named, laid out and written. It applies to every handwritten `.cs` file in the repository, including tests and tools. Third-party sources under `extern/`, generated files (`**/Generated/*.cs` and files carrying an `<auto-generated>` header) and the cases listed in [section 16](16-exceptions.md) are out of scope.

The [coding rules](../coding.md) own design, error-handling, resource and change-management requirements. This rulebook is the detailed authority for names and layout.

- Every rule has an ID such as `B-05`. Cite the ID in reviews and commit messages.
- Each rule states the requirement first, then shows a compliant example. A block introduced by **Avoid** shows what the rule forbids.
- "Must", "always" and "never" are requirements. "Prefer" and "recommended" describe the default; deviate only when the default hurts readability.
- External contracts take precedence over this rulebook: interface implementations, overrides, MSBuild task parameters, serialized names and native interop signatures keep the names their contract requires (see [section 16](16-exceptions.md)).
- Formatting changes and renames are separate changes. A formatting-only change must not alter names, logic, execution order or public contracts. Renaming a public member is an API change.
- Automatic formatters must preserve these rules. Do not apply a formatter whose output differs from this rulebook.
